# Project Harness · 项目开发与维护技能

把项目进度、模块约定和可独立运行的测试入口持续维护在项目自己的 `harness/` 中。

## 适用场景

- 新项目：逐步建立最小 Harness 与项目维护规则。
- 老项目：复用已有文档和测试，补齐本次涉及的关键业务。
- 日常开发与修复：读取现状、完成改动、验证并同步记录。
- 换会话或仅验收：核对代码与进度，接续工作或独立运行测试。

## 安装与使用

这是一个独立技能包，仓库根目录就是技能目录。

最小安装只需下载 [SKILL.md](https://raw.githubusercontent.com/oinsist/project-harness/main/SKILL.md)，保存为当前项目的 `.agents/skills/project-harness/SKILL.md`，无需克隆整个仓库。

`agents/openai.yaml` 仅用于界面显示和默认提示词，可选；`README.md` 是使用说明，也无需安装。当前技能正文自包含，不依赖其他仓库文件。

只安装在项目级目录，不安装到 `~/.agents/skills/` 或 `~/.codex/skills/`。已有同名项目技能时更新该项目内的副本。

在项目聊天中选择技能，或明确说明：

```text
使用 $project-harness。
```

```text
使用 $project-harness，修复【问题】，验收标准是【预期行为】。
```

首次使用会根据项目现状建立并填写 `harness/`，同时在根目录 `AGENTS.md` 写入引用本地技能的持续维护约定；已有相应内容时只补齐缺项，不重复追加。即使项目已有其他工具规则文件，也不能用它替代这一步。

后续 Agent 从 `AGENTS.md` 读取约定，在每次修改项目后、交付之前，按照本地技能维护受影响的进度、模块说明和测试入口。用户无需每次另写初始化和持续维护的长提示词。

每个需要使用的项目分别下载、安装这份技能。各项目分别保有自己的进度、模块说明与测试；更新仓库版本后，已安装的项目需要覆盖其本地 `SKILL.md` 才会使用新版。

技能自身不依赖其他技能或 MCP 服务；实际项目测试需要相应的运行环境。技能负责指导建设与维护，具体测试入口必须在目标项目中创建并验证。

格式及本地发现机制参见 [OpenAI 技能说明](https://learn.chatgpt.com/docs/build-skills)。列表未刷新时可重启后查看。

## 技能包结构

```text
project-harness/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── README.md
```

目标项目中按实际需要建立：

```text
harness/
├── README.md
├── progress.md
├── modules/
└── tests/
```

已有测试直接复用，不复制业务实现；未运行、跳过或受阻的范围如实记录，不能标为已验证。自动测试通过与用户人工验收分别记录。

## 验证范围

已通过技能格式检查，并在临时新、老小项目中试用初始化、维护、重复验收及故障检出。尚不能据此保证所有技术栈或复杂业务的效果。
